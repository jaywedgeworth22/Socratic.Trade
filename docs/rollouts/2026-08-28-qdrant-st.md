# Qdrant for Socratic.Trade — deployed 2026-08-28

Owner-directed (2026-08-28): the shared Hetzner box was upgraded to double capacity and Qdrant now runs on it as the self-host path for ST's RAG (Plan A of the 2026-08-27 fleet ops review).

## What exists

- Coolify service `qdrant-st`, image `qdrant/qdrant:v1.19.0`, on the production server.  Port 6333 is bound to the server's Tailscale mesh IP only — no public FQDN, no Traefik route.  API key required (Coolify-generated service env).  Capped at `mem_limit 6g` / `cpus 3` so prod trading is never starved.
- Collection `socratic-trade`: 1024-dim cosine, on-disk vectors, int8 scalar quantization (always_ram), payload tenant index `ns` (`is_tenant=true`, one tenant per Pinecone namespace), keyword index `embed_model`.
- ST Infisical prod holds `QDRANT_URL` and `QDRANT_API_KEY`.  Host/UUID specifics live in fleet-ops `ATTACK-MAP.md` (private), not here.

## The copy

`scripts/qdrant/pinecone-to-qdrant-copy.py` (stdlib-only Python, resumable via a state file) copies every Pinecone namespace into the collection.  Owner rule: copy ALL non-Voyage embeds.  Records without `embed_model` metadata are voyage-era legacy — they are invisible to current bge-m3 retrieval (its filter requires the field), so the copy keeps exactly the records retrieval can see today and drops `voyage-*` plus untagged legacy (<2%).

Point ids are `uuid5("st:" + namespace + ":" + pinecone_id)`; the original id is kept in payload `pc_id`, the namespace in payload `ns`.

Run with `PINECONE_API_KEY`, `QDRANT_URL`, `QDRANT_API_KEY` in the environment.  Read-only against Pinecone.
