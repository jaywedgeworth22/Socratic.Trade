# Codex Review Follow-up for PR #1476 — Accessibility + Styling Fixes

## Summary

PR #1476 (`ag/theme-selector`, merged `d236f9d`) received a Codex review after merge with 5 P2 findings. This follow-up branch addresses all 5 items against current `main`.

## Changes

### 1. Toggle aria-labels (`app/console/settings/page.tsx`)

Three `<Toggle>` instances (lines 162, 320, 413) were missing their `label` prop, which supplies `aria-label` on the switch button. The `LabeledContent` visible label is not programmatically associated — screen readers and voice control could not target the switch.

**Fix:** Added `label="Require typed confirmation"`, `label={type}`, and `label="Auto-resume on boot"` respectively.

### 2. Mobile layout (`app/ui/ios-components.tsx`)

`LabeledContent`'s left column used `shrink-0`, preventing the label from shrinking on narrow viewports, while hints could occupy up to `280px`. On small screens this caused overflow.

**Fix:** Removed `shrink-0` from the label column; changed hint `max-w-[280px]` → `max-w-[min(280px,40vw)]`.

### 3. Console-scoped colors (`app/ui/ios-components.tsx`)

`LabeledContent` used global `text-fg`/`text-muted` Tailwind classes, which don't respond to `.console-root[data-theme]` palette changes. Toggling the console theme left these rows visually pinned.

**Fix:** Changed `text-fg` → `text-[color:var(--con-fg)]` and `text-muted` → `text-[color:var(--con-muted)]` — matching the pattern already used by `NavigationLinkRow` in the same file and all console CSS tokens.

### 4. Valid HTML — block labels in `<span>` (`app/ui/ios-components.tsx`)

The delivery channel row passes a `<div>` (with flex-wrap chips) as the `label` prop. `LabeledContent` wrapped every label in a `<span>`, producing invalid `<span><div>…</div></span>` markup.

**Fix:** Changed the `<span>` wrapper to `<div>`. Visually identical (inside a `flex` container); avoids the spec violation.

### 5. Input aria-label (`app/console/settings/page.tsx`)

The notification webhook `<input>` had no `aria-label` or `for`/`id` association with its visible label (rendered as an unrelated `span` by `LabeledContent`). Only `title` was present, which is unreliable for accessibility.

**Fix:** Added `aria-label="Webhook URL"`.
