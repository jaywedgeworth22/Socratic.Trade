## Summary

Addressed 5 remaining Codex review findings from the now-merged PR #1541 (`agent/ag-red-team-fallback`). The PR was already merged before these threads were resolved, so this is a follow-up PR fixing the issues on `main`.

## Changes

### 1. (P2) Pass account target when saving fallback models
**Files:** `app/console/strategy/page.tsx`

Both `commitFallbackModels` and `commitRedTeamFallbackModels` omitted `policy.connectedAccountId` from their `savePolicy()` calls. A concurrent account switch could persist the fallback list onto the wrong account. All nearby model/prompt writes pass the explicit account ID.

**Fix:** Added `policy.connectedAccountId` as the second argument to both `savePolicy()` calls.

### 2. (P2) Avoid logging FMP URLs with API keys
**Files:** `src/lib/fmp-gamma.ts`

`fetchFmpJson` logged the full request URL on non-ok responses. Every caller appends `apikey=${apiKey}` to the URL, so a transient 403/5xx would write `FMP_API_KEY` into server logs.

**Fix:** Added `sanitizeFmpUrl()` helper that strips the `apikey` query parameter before logging.

### 3. (P3) Update attempted model before transport failures
**Files:** `src/lib/red-team.ts`

`finalModel` was only reassigned at line 363, after a successful `response.json()` parse. When a fallback model times out or hits a transport error, the outer catch still reported the primary model, making the broken key/provider harder to diagnose.

**Fix:** Moved `finalModel = attempt.model` to the top of each loop iteration, before the try block, so every attempt updates the tracking variable regardless of where it fails.

### 4. (P3) Commit fallback edits when focus leaves
**Files:** `app/console/strategy/page.tsx`

`FallbackModelSelect` saved changes on Enter key or mouse click outside, but not on keyboard-driven blur (Tab key). Keyboard-driven edits could be silently lost.

**Fix:** Added an `onBlur` handler to the `TextInput` that commits via `setTimeout(0)` to let any in-flight checkbox `onChange` events settle first.

### 5. (P3) Degrade unavailable FMP endpoints instead of throwing
**Files:** `src/lib/fmp-gamma.ts`

`fetchFmpJson` threw on every non-ok response. All callers are array-returning endpoints and expect graceful degradation (empty array on transient 403/5xx).

**Fix:** Changed the non-ok path to return `[]` as the degraded fallback instead of throwing.
