# 2026-07-04 — Tokenless git dependency for congress-trading-shared (consumer switch)

## Summary

`congress-trading-shared` is now a public repo. The owner directed every consumer off the
private GitHub Packages registry (npm auth via `NODE_AUTH_TOKEN`/PAT) onto a tokenless git
dependency instead. This note covers the **Socratic.Trade consumer switch**: pin
`package.json` to `github:jaywedgeworth22/congress-trading-shared#semver:^1.2.x`, regenerate
the lockfile tokenlessly, and strip every CI/script reference whose only purpose was
authenticating that one private package.

## Why

Owner-directed: the shared package moved from private-GitHub-Packages to a public repo, so
the `NODE_AUTH_TOKEN`/scoped-registry auth path this repo carried is no longer needed and is
extra surface area (secrets, `.npmrc`, a bespoke install-wrapper script) for zero benefit now.

## Proof: tokenless install

Scratch-dir proof (before touching this repo), `NODE_AUTH_TOKEN` unset the whole time:

```bash
mkdir /tmp/tokenless-proof && cd /tmp/tokenless-proof && npm init -y
npm install "github:jaywedgeworth22/congress-trading-shared#semver:^1.2.x"
node -e "console.log(Object.keys(require('@jaywedgeworth22/congress-trading-shared')).slice(0,8))"
```

Result: install succeeded, `dist/` was generated by the package's `prepare` script during
install, and 8 named exports (`API_PATHS`, `AnalystRowSchema`, ...) imported correctly.

In-repo proof (this worktree), after editing `package.json`:

```bash
env -u NODE_AUTH_TOKEN npm install --package-lock-only   # regenerates package-lock.json
```

Then a from-scratch CI simulation copying just `package.json`/`package-lock.json` into an
empty dir:

```bash
env -u NODE_AUTH_TOKEN -u GIT_SSH_COMMAND -u SSH_AUTH_SOCK GIT_SSH_COMMAND=/bin/false npm ci
```

`GIT_SSH_COMMAND=/bin/false` deliberately breaks SSH so the install can only succeed if git
resolves the `github:` shorthand over HTTPS smart-transport — it did: `added 743 packages`,
`dist/` present, 70 named exports importable. The lockfile's resolved entry does read
`git+ssh://git@github.com/...` (npm's internal git-URL normalization), but the actual fetch
plainly did not require a working SSH transport in this test, confirming a genuinely tokenless,
keyless install path.

Then the real worktree install: `env -u NODE_AUTH_TOKEN npm ci` — succeeded (743 packages).

## What did NOT change (deliberately out of scope)

- `.github/workflows/shared-package-pin-check.yml` — untouched. Its `GH_PACKAGES_TOKEN` use is
  for a **different** purpose (reading Congress.Trade's `app/package.json` via the GitHub API
  to compare pinned versions across the two consumer repos), not npm registry auth. Its
  `norm()` version-comparison helper strips a leading semver range operator
  (`^~><=`) from a bare version string; it has not been updated for the new
  `github:...#semver:^1.2.x` spec shape and will likely need a follow-up once both consumers
  carry the git-dep spec (see Follow-ups).
- The "Refuse untrusted PR source" fork/bot gate in `ci.yml`/`e2e.yml` — left functionally
  intact even though the secret it protected (`GH_PACKAGES_TOKEN`/`CONGRESS_TRADING_SHARED_DEPLOY_KEY`)
  is now gone and its error message ("private-repo deploy key secret") is stale. Removing a
  same-repo-only CI gate is a security-posture decision beyond "strip token wiring whose only
  purpose was this package" — flagged as a follow-up instead of silently removed.
- `.env.example` — had no `NODE_AUTH_TOKEN`/registry lines to begin with; nothing to change.

## Follow-ups

- `shared-package-pin-check.yml`'s peer-comparison `norm()` helper compares bare semver
  strings; once Congress.Trade also carries a `github:...#semver:^1.2.x` spec, verify the
  comparison still behaves sanely (it will compare the full git-URL strings, which should
  match if both repos use an identical spec string, but a future exact-tag vs semver-range
  mismatch between the two repos would no longer be caught the same way a bare-semver mismatch
  was). Not touched here since both consumer PRs need to land before there's anything real to
  compare.
- Consider whether the fork/bot "Refuse untrusted PR source" gate in `ci.yml`/`e2e.yml` should
  be removed or its message corrected now that there's no secret behind it — owner decision,
  not made unilaterally here.
- Congress.Trade gets its own separate PR/rollout note under that repo's own AGENTS.md
  conventions (see that repo's `docs/rollouts/` and effort-log boards).
- `codex/package-git-prepare-20260629` / `codex/package-prepare-and-ci` (shared repo) remain
  un-deleted per that repo's own rollout note's explicit recommendation — a future
  branch-hygiene pass in that repo can delete them.
