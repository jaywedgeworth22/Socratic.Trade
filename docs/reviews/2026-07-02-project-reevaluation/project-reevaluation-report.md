## PART 1 — Blind bottom-up designs

### Steadyhand — Novice-First Agentic Trading Interface

Steadyhand designs the entire interface around three permanently answered questions: is this real money, is the agent armed, and what can it spend. Global chrome carries a word-first Reality Ribbon (TEST/PAPER/BROKERAGE, with a persistent crimson viewport frame in live mode), an Account Scope Pill, an Armed Chip (Running/Frozen/Exit-only/Winding-down x Ask-first/Autopilot), a live remaining-daily-spend meter, and an always-visible FREEZE button. Navigation is seven task-verb destinations (Home, Approvals, Activity, Results, Strategy, Ask, Settings) plus an allowlist-only Admin console. Onboarding runs entirely on play money and includes a mandatory Fire Drill where the user practices the emergency stop before anything trades. Real money is reached via a Graduation Ladder (Test to Paper to Brokerage to Autopilot) with earned checklists, a computed worst-case-dollar paragraph, cooling-off timers, and semantic typed phrases (APPROVE LIVE NVDA, ARM REAL MONEY 4821). Friction is asymmetric: stopping and tightening limits are one tap; starting, loosening, and spending require typing the meaning. All ~50 policy fields collapse into an editable plain-English Guardrail Sentence with sliders; advanced dials sit behind progressive disclosure with reset-to-safe. Every buy, sell, block, and skip produces a layered Decision Receipt: one-line summary, provenance-stamped evidence, the bull/devil's-advocate debate, gate-by-gate rule arithmetic, sizing math, and outcome-since. Rejected and blocked ideas feed a counterfactual scoreboard ("the ones you said no to") that calibrates user trust honestly. System fail-safes (boot disarm, red-team-unavailable downgrades, hourly-cap self-demotion, reconciliation states) are narrated in plain words rather than silent. Settings split cleanly: anything that can spend money is account-scoped inside an account-framed Strategy page; anything about the person is global and tagged. The document includes text wireframes for all major surfaces, six step-by-step high-stakes flows, a measurement plan centered on safety comprehension and trust calibration, and ten operating principles.

**Most novel ideas:**
- Reality Ribbon + crimson viewport frame: money-reality as ambient, word-first chrome — live mode literally borders every screen in red, so peripheral vision knows you're in the real-money room.
- Mandatory Fire Drill onboarding: users must practice pressing FREEZE and reading the emergency sheet on fake money before any broker connect, with scheduled repeat drills — the first emergency-brake use must not be an emergency.
- Graduation Ladder: real money is a level you earn (Test -> Paper -> Brokerage -> Autopilot) with visible gate checklists, a live-computed worst-case-dollar paragraph, and a 24-hour cooling-off before autopilot.
- Guardrail Sentence: all ~50 policy fields render as one editable plain-English paragraph with slider-bound values; loosening a limit on a live account demands typed confirmation while tightening is always one tap (asymmetric friction).
- Decision Receipt: a single standardized artifact for every buy, sell, block, and skip — short version, provenance-stamped evidence, the bull vs devil's-advocate debate, gate-by-gate arithmetic, sizing math, and what happened since.
- 'The ones you said no to' counterfactual scoreboard: rejected/blocked ideas are tracked from decision price and compared against approvals, telling users honestly whether their vetoes add value and normalizing rejection as data.
- Narrated fail-safes: boot disarms, red-team-unavailable downgrades, hourly-cap self-demotion, and reconciliation states are announced in plain words in the feed — silent safety reads as flakiness; narrated safety builds trust.

### TradeDeck: Operator-First Fleet Console

TradeDeck treats each connected account as an independent "lane" (its own policy, cadence, systemState, authority) and makes fleet supervision the home surface. Navigation has two orthogonal axes: destination (10 number-keyed rail items: Fleet, Approvals, Runs, Positions, Strategy, Risk & Tax, Analytics, Market, Chat drawer, admin Ops) and scope (a persistent Scope Bar: ALL LANES or one lane), so every screen unambiguously answers "which account, which money." Money-reality (Test/Paper/Brokerage) is ambient: a full-height Reality Rail encodes it in color plus texture (amber diagonal stripes for live) alongside the mandatory word label, applied per-object so a live proposal inside a mixed queue is individually marked. A Cmd+K command palette with an "@lane verb" grammar is the keyboard spine, backed by the durable idempotent command queue and showing a server-resolved preview (lane, reality, effect) before commit. Emergency controls (HALT LANE / HALT ALL) are permanently in the header with explicit "nothing will be sold" copy; friction is asymmetric — one click to stop, a full Arming Console with server-verified preconditions and typed phrases to start. Approvals are keyboard-triaged diff cards foregrounding what changed since proposal (drift, revalidation note, since-proposed counterfactual, live gate-preview) with the APPROVE LIVE <SYMBOL> typed challenge embedded inline. The Run Inspector renders the full forensic chain — pipeline timeline, chosen vs skipped candidates with since-decision counterfactual returns and per-field provenance chips, verbatim gate reasons, Red Team transcripts, sizing math. Risk & Tax shows every cap as a consumption gauge plus cross-account wash-sale lockouts and days-to-long-term countdowns; live-lane policy edits route through a Blast Radius sheet computing immediate consequences before a typed commit. The doc specifies six step-by-step high-stakes flows, a per-lane vs per-user vs admin settings taxonomy expressed through chrome, a nine-point safety model, ledger-derived success metrics, and ten design principles.

**Most novel ideas:**
- Reality Rail: a full-height color+texture edge band (amber diagonal stripes = live) paired with word labels, applied per-object, so money-reality survives screenshots, grayscale, and colorblindness at any pixel distance.
- Authority Ladder glyph: a 4-cell strip (halted/close_only/active-propose/active-decide) per lane; the decide cell stripes amber on live accounts, making the fleet's danger posture readable in one saccade.
- Approvals as diffs, not tickets: cards foreground what changed since proposal (price drift vs cap, revalidation note, counterfactual so far, live server gate-preview), with the typed live challenge embedded inline.
- Blast Radius sheet: editing a risk limit on a live lane previews server-computed immediate consequences (new headroom today, which blocked proposals would now pass, interaction with decide authority) before a typed commit.
- Command palette grammar '@lane verb args' as a thin client over the durable mobile-command queue, with a mandatory preview line resolving lane + money-reality + effect before any commit.
- Regret Ledger: counterfactual 'since-decision' returns rendered as a first-class column on every skipped/rejected/blocked idea, plus an analytics tab comparing human rejections vs machine skips.
- Asymmetric friction doctrine: halt is one click anywhere with 'nothing will be sold' copy; arming/resuming is a full-screen console with live server-verified preconditions and typed phrases; un-halt is never on the stop button.

### Ledgerline: The Auditable Autopilot

Ledgerline organizes the entire product around the decision lifecycle (signal -> thesis -> adversarial challenge -> policy gate -> approval -> execution -> outcome -> learning): the left-nav spine is literally lifecycle-ordered (Now, Signals, Runs, Decisions, Positions & Orders, Outcomes, Learning), with a separate "Law" section (Strategy Studio for the offense, Risk & Policy for the cage). The universal atom is the Decision Dossier: a permalinked per-trade page rendering all eight lifecycle stages as an evidence chain, including per-field data provenance chips, the verbatim red-team bear case, the itemized 31-check gate verdict with a LIVE pre-check at approval time, typed live confirmation, execution truth (idempotency refId, reconciliation states), realized outcome, and which scorecards the trade feeds. The dossier doubles as the approval surface and the permanent audit record. Global chrome is an unhideable Reality Bar: word-first money-reality chip (Test/Paper/Brokerage - real money), state word, authority word, a live Spend Odometer against daily caps, next-run countdown, and a one-gesture HALT whose interstitial teaches "halting never sells." Configuration is treated as versioned law: edits accumulate into a reviewed diff with impact preview and required note, appending to an immutable Policy Ledger (human, mobile, tuner, and breaker changes side by side, each revertible via a new reviewed diff). A Counterfactual Shelf keeps score on rejected/blocked/withdrawn/skipped ideas both ways. Safety rests on asymmetric friction (stopping instant, arming/loosening ritualized with typed object-specific phrases), ambient reality, persistent danger banners, pre-flight over post-hoc errors, and stating inherited invariants on the controls that embody them. Includes six step-by-step high-stakes flows, a blast-radius-stamped settings taxonomy, mobile as a queued-command remote (approve is never a swipe), and measurable success criteria centered on reality-identification accuracy, dossier depth before decision, and time-to-reconstruct any trade.

**Most novel ideas:**
- Decision Dossier: one permalinked page per trade rendering all 8 lifecycle stages as an evidence chain (provenance, thesis, verbatim bear case, itemized gate verdicts, execution, outcome) - both the approval surface and the permanent audit record.
- Reality Bar with Spend Odometer: unhideable chrome with word-first money-reality (Test/Paper/Brokerage), state and authority words, live daily-cap consumption, and a one-gesture HALT - every screenshot carries the money truth.
- Policy-as-law commits: no silent saves - every edit becomes a reviewed diff with live impact preview, direction-aware friction (loosening needs a typed word + note), appended to an immutable, revertible Policy Ledger of all change actors.
- The Counterfactual Shelf: rejected, gate-blocked, withdrawn, and skipped ideas kept as first-class outcomes with realized since-then returns and a who-said-no column, scoring the human and the cage against each other in the open.
- Live gate pre-check inside approval: the dossier re-computes drift, cap headroom, wash-locks, and staleness before the user commits, swapping the Approve button for the block explanation when it would fail - pre-flight over post-hoc error.
- Asymmetric friction doctrine: halting is one gesture with no typed text, while arming, granting decide authority, and loosening limits require checklists, rehearse-in-Paper nudges, and typed object-specific phrases (ARM ROTH IRA, APPROVE LIVE NVDA).
- Invariants written on their controls: 'Halting never sells' on the stop screen, exit-exempt gate checks struck through as 'exempt - exit', 'manual runs can only propose' on the run button - the UI states each guarantee at the moment it matters.

- **P2 [debt/M] LLM eval harness never runs in CI and covers zero cases for the money-deciding strategy prompt** (`scripts/eval/dataset.ts`) — Regressions in the trade-proposal system prompt (strategy.ts:2017) or a model swap ship with no quality gate; the 16-case harness gives false confidence since CI never runs it and offline mode cannot see prompt changes. *Evidence:* dataset.ts:38 — task union is chat/quote/intent-* only, despite the header (lines 4-9) claiming a 'strategy / reasoning' family; ci.yml:72-75 runs lint/test/build with no eval step; run-offline.ts default mode scores only MockLLM (its own canned stub). *Fix:* Add eval:offline to the verify workflow (hermetic, pins tool schemas + safety cases) and add strategy-prompt cases: schema conformance, side gating (short disabled), refusals — run real-provider mode on a schedule.
- **P2 [debt/S] Strategy system prompt is unversioned; strategy_runs persist no prompt identity for the learning loop** (`src/lib/strategy.ts`) — Reflection/thesisOutcomes feed prior-run results back into the model with no record that the deciding prompt changed between runs; a live-money behavior change cannot be attributed to a prompt edit vs market conditions. *Evidence:* strategy.ts:2017 builds the trading system prompt inline with no version constant, while the chat prompt has PROMPT_VERSION='agentic-chat@0.7.0' (src/lib/chat/prompt.ts:5); db-execution.ts:228 inserts strategy_runs with only (id, user, account, started_at, status) — no prompt hash/version. *Fix:* Add a STRATEGY_PROMPT_VERSION constant plus a sha256 of the assembled static prompt sections; persist both on strategy_runs and surface in run detail / ops snapshot.
- **P3 [risk/S] Auth for a real-money app rides on next-auth 5.0.0-beta with a caret range, plus hand-rolled cookie coupling** (`package.json`) — A routine bump within the caret range can pull a later beta that renames cookies or changes token encoding, breaking login or the middleware fail-closed gate; betas carry no security-patch guarantees. *Evidence:* package.json: "next-auth": "^5.0.0-beta.31" (lockfile resolves beta.31); src/lib/auth/session-edge.ts:11 hardcodes ['__Secure-authjs.session-token','authjs.session-token'] and uses the cookie name as JWT salt, re-implementing Auth.js internals for the edge gate. *Fix:* Pin next-auth exactly, add a dependabot ignore like the eslint@10 case, and add a test asserting encodeSessionToken round-trips through getSessionEmail so a breaking bump fails CI.
- **P3 [debt/S] audit_events, llm_usage, and chat_turns grow unbounded — no retention outside full account deletion** (`src/lib/db.ts`) — The production SQLite file grows monotonically (inflating Litestream replica size/cost and ops snapshots); created_at scans degrade over months of 60s-tick autonomous operation. *Evidence:* db.ts:413 inserts an audit_events row per audit() call (98 call sites, incl. per alert trigger); llm-usage.ts:111-129 inserts one row per LLM call; the only DELETEs for these tables are account-deletion.ts:262-268.
