# Design Adjudication — Three Blind Designs vs. the Approved Nav-v2 Plan

**Adjudicator brief.** Three designers who had never seen the current UI designed the product bottom-up from the capability inventory alone: **Steadyhand** (novice-first), **TradeDeck** (operator-first fleet console), **Ledgerline** (explainability-first "the audit trail is the interface"). This document adjudicates them against each other and against the owner-approved redesign (`docs/settings-navigation-redesign.md` + `spec/`, PRs #1–#8 landed or in-flight, #9–#14 pending). Where I claim the plan "lacks" something, I verified it by grepping the spec folder (e.g., `calibration` returns zero hits outside grounding; `learned-context` returns zero hits; the Approvals card spec's ten enumerated elements; `01-global-frame.md:336`'s STOP copy; `01-global-frame.md:168/182`'s Fleet aggregate).

The epistemics matter: the approved plan was itself synthesized from four teams including two blind ones, so *some* convergence with these three new blind designs is expected and only weakly confirmatory. What is strongly evidential is (a) convergence among these three independent designs on things the plan **doesn't** have, and (b) places where all three, reasoning from the same capability inventory, contradict a specific plan decision.

---

## 1. CONVERGENCE — what independent blind designers agreed on

### 1.1 Unanimous (3/3) and also in the plan — the plan's spine is confirmed

1. **Word-first, ambient money-reality in persistent chrome.** Steadyhand's Reality Ribbon + crimson viewport frame, TradeDeck's Reality Rail (color **plus texture** — diagonal stripes so screenshots and colorblind rendering survive), Ledgerline's Reality Bar with typographically distinct chips. All three make Test/Paper/Live a *chrome* fact readable from any pixel distance, words load-bearing, color reinforcement only. This is the plan's P5 (`PAPER · practice money` word-class badges + red Live hairline), independently re-derived three times. All three also converge on the plan's exact three-word vocabulary because the inventory's `deriveExecutionState` invariant forces it — a nice confirmation that the server contract is the right source of truth for the chrome.

2. **Approvals is a dedicated top-level destination with the app's only red badge.** All three call it, in nearly identical words, "the only place the human is load-bearing" (TradeDeck), "one place to check for 'the robot needs me'" (Steadyhand), "the heart of the product" (Ledgerline). Matches plan destination #2 exactly, including expiry countdowns, drift-vs-anchor meters, debate transcripts, and rejection-feeds-learning (the reject-reason chip taxonomy in spec/02:216 is essentially Steadyhand's chip list).

3. **Asymmetric friction: one gesture to stop, a ritual to start; typed phrases that name the object.** All three state the identical principle — "stopping is instant, starting is a ritual," "friction mirrors risk, asymmetrically," "one key to stop, a ritual to start" — and all three reserve typed confirmation for risk-*increasing* acts only. This is plan P9. All three also independently insist typed phrases contain the object of consent (`APPROVE LIVE NVDA`, `ARM ROTH IRA`, `LIQUIDATE <LABEL>`, `WIND DOWN 4821`) rather than generic tokens — see §5 amendment on the plan's generic `ARM LIVE AUTONOMY` / `SELL LIVE POSITIONS` phrases.

4. **STOP never sells; liquidation is a separate, heavier act.** Unanimous, and unanimous *for the same stated reason*: an operator under stress must never hesitate on the halt button fearing a fire-sale. This directly validates the plan's STOP/Flatten split (PR #9), the single most safety-critical pending change. (But see §1.2 item 3 and §4.4 — all three also converge on a nuance the plan's copy currently gets wrong.)

5. **Chat drafts, rails execute.** All three ban execution from the assistant, render draft tickets as a visually distinct "not real yet" species, and promote drafts into the one approval rail. Matches the plan's "the AI never gets a side door" (P7) and the Assistant-routes-to-Approvals rule.

6. **Config splits by scope first, and the scope is stamped on the surface.** All three independently drew the plan's exact governing line: *how this account trades* lives with the account; *who you are and how the platform reaches you* is user-global; platform plumbing is admin. Ledgerline literally stamps every settings surface with its "blast radius" top-right; TradeDeck tints per-lane editors with the lane's reality; Steadyhand frames the Strategy page in account-colored chrome. Both TradeDeck and Ledgerline even independently handled the awkward `marketScanCandidateLimit`/`outlierReserve` overlay the same way the owner resolved Open Q1: keep it user-global and *label* it "applies to every account." This is about as strong as convergent evidence gets for the plan's Scope A/B split and the printed governing rule.

7. **Presets copy, never link, and can never arm.** All three restate the inventory's copy semantics on the Apply control itself and add an explicit "never changes running/armed state" reassurance line. Matches plan P8 and the PR #7 mirror-deletion.

8. **First-run = Test, zero credentials, run-once as the first act, land in the approval queue; broker connection deferred.** All three build onboarding as "watch it think on fake money within minutes." Matches spec/10's Test auto-provision + "Take a practice run" CTA + progressive unlock.

9. **Counterfactual accountability.** All three surface the roads not taken (rejected/blocked/skipped with since-decision returns) as trust infrastructure — Steadyhand's "ones you said no to," TradeDeck's Regret Ledger, Ledgerline's Counterfactual Shelf. The plan has Results→Counterfactuals and Scan→skipped, so the *surface* exists; the blind designs go further on the summary layer (§3).

10. **Honest absence and provenance.** All three render `n/a` vs `-` distinctly, timestamp everything, badge synthetic spreads, and refuse fabricated numbers — inherited straight from the inventory's invariants, confirming those repo conventions should be UI-visible, not just data-layer rules.

### 1.2 Unanimous (3/3) but **not** in the plan — the highest-value findings

1. **A run-level forensic surface.** Steadyhand's Run Story + Decision Receipt, TradeDeck's Runs destination + Run Inspector, Ledgerline's Runs station + Decision Dossier. All three independently concluded that *the run is the atomic audit unit* and built a drill-in showing: the pipeline timeline (breakers → hygiene → scan → propose → red-team → gate → execute), the **chosen-AND-skipped candidate table with since-decision counterfactual returns and skip reasons**, gate events verbatim, and per-candidate evidence with provenance. The backend already persists all of it (`signal_snapshot`, `candidates_considered`, gate events, rationale diversity). The plan has **no** runs surface: PR #2's mapping folds the Runs feed tab toward Results→History, which spec/03 defines as a flat audit-log table (timestamp/actor/action/before→after). Three-of-three blind convergence on a surface the plan omits is the strongest single signal in this exercise.

2. **A permalinked per-decision "why" artifact.** Steadyhand's Decision Receipt and Ledgerline's Decision Dossier are the same object designed twice: one canonical, layered page per proposal/fill/block/skip (short version → evidence with per-field provenance → the bull/bear debate → the gate arithmetic → sizing math → what happened since), identical grammar for all outcomes, the deep-link target of every notification, reachable from chat. TradeDeck reaches the same artifact through the Run Inspector. The plan's Approvals card carries most of the *pending-state* evidence but has no durable, addressable, post-hoc artifact; spec/02 routes "rejected/expired → Results→History" (a log row, not a dossier).

3. **The STOP flow must disclose that halting pauses app-managed protective exits — and offer close-only as the middle verb.** All three designs make this the load-bearing sentence of the emergency flow: "Nothing buys, nothing sells — **not even your automatic stop-losses**" (Steadyhand); "No runs, no orders, **no synthetic-stop exits** … Want exits to keep running? Use CLOSE-ONLY instead" (TradeDeck, offered inline in the halt sheet); "freeze everything **INCLUDING protective stop exits** … positions stay open and unguarded by this app; broker-held brackets keep resting" (Ledgerline). The inventory is emphatic that `halted` is the one state where the synthetic stop monitor is off. The plan's STOP is one-click **with no confirm** and its tooltip reads "**Always safe** — never sells anything you hold" (spec/01:336, spec/09:153). For a live account relying on synthetic trailing stops, "always safe" is not quite true: halting removes the app's protection. This unanimous finding challenges the plan's copy, not its mechanism — see amendment A1.

4. **Data freshness and the next-run clock belong in the chrome.** Steadyhand's freshness footer ("Data as of 2:41 PM · quotes delayed ~15 min · next run in 22 min"), TradeDeck's status strip (scan asOf, quote-delay disclosure, scheduler-heartbeat age as a liveness canary), Ledgerline's Reality Bar next-run countdown + event ticker. The plan puts the next-run countdown on Dashboard only and has no freshness element in the shell. The inventory explicitly says the interface "should surface timestamps rather than promising real time" — three designers read that and put it in the chrome.

5. **Automatic state transitions narrate themselves persistently.** Boot-interlock reverts, breaker trips, hourly-cap auto-demotion to propose, proposal withdrawals — all three render these as placed, persistent banners with cause + timestamp + sanctioned next actions ("toasts are never the only witness" — TradeDeck; Ledgerline's dismiss-only-by-reading boot banner; Steadyhand's plain-words interlock narration). The plan builds the *mechanism* (PR #7's autonomy-reset-on-restart sweep) and shows state suffixes (`‖ HALTED`), but specifies no cause-narration UI anywhere.

6. **Per-position protection status.** Steadyhand's 🛡 per position, TradeDeck's protection column with red UNPROTECTED flags, Ledgerline's protection column + "5/5 covered, 3 broker-held / 2 synthetic" coverage stat with the honesty distinction "broker-held survives app downtime; synthetic requires the app up." The plan's Dashboard positions list has no protection column (grep confirms).

7. **Confidence calibration is surfaced — and is the evidence for granting Decide.** All three include the calibration readout ("when it says 80, it's right 61% of the time"); Ledgerline calls it "the single most important chart for deciding whether to ever grant decide authority" and embeds it *in the arming flow*; Steadyhand shows the approval-rate readout at Autopilot rung 3. The backend computes calibration today (inventory §3.10). The plan's Results Scorecards are thesis/regime/factor only; `calibration` appears nowhere in the spec.

### 1.3 Majority (2/3) convergence worth weight

- **One consent inbox / "needs you" aggregation.** Steadyhand merges Learning approvals (pending learned-context + tuning proposals) into the Approvals inbox as sub-tab; TradeDeck puts them in the same queue with distinct card shapes; Ledgerline aggregates everything human-blocking (approvals, pending learned facts, reconciliation orphans) into a "NEEDS YOU" block on the home. The plan relocates the Tuning queue to Results but leaves the learned-context queue *entirely unplaced* (zero spec hits) — today it's a legacy chrome badge.
- **Reconciliation states as first-class UI.** TradeDeck and Ledgerline both promote `placing_failed`/`pending_reconciliation` to visible cards with plain-language "intent recorded; broker truth will reconcile; do not retry" copy — Ledgerline's "No orphans" empty state is a small masterpiece of trust copy. Absent from the plan.
- **Approval-time gate result should be a *live* server pre-check.** TradeDeck ("show the server's verdict before the commit… an approval that would fail shows the failure before the click") and Ledgerline (stage 4 "is live, not archival"). Spec/02 renders the gate checklist from the same engine but shows a blocked proposal's `reasons[]` "from the snapshot" — ambiguous about freshness on *pending* cards.
- **Thesis track record inline on the approval card.** TradeDeck ("thesis Momentum-Breakout · lane win-rate 61%, n=23") and Ledgerline (stage 2 embeds the thesis×regime scorecard — "the single most decision-useful context the system can offer an approver"). Not among spec/02's ten card elements.
- **The human's own veto scorecard.** Steadyhand ("your rejections would have returned +2.1% avg · your approvals +3.4% — your judgment is adding value") and Ledgerline's shelf summary line. The plan's Counterfactuals sub-tab replays individual decisions but has no aggregate am-I-helping verdict.
- **Soft rehearsal/experience gates before Live.** Steadyhand's Graduation Ladder (visible gate checklists, ≥N decisions, verified notification channel, 24h cooling-off for Autopilot) and Ledgerline's rehearsal interpose ("this rulebook has never traded in a sandbox — run it once in Paper first, or type why"). The plan has typed rituals and progressive destination unlock but no earned/experience gates.

## 2. DIVERGENCE — where the designs disagree, and who is right for this product

**D1 — Shape and size of primary nav.** Steadyhand: 7 task-verb tabs. TradeDeck: 10 dense destinations (adds Runs, Positions, Risk & Tax, Market as top-level). Ledgerline: a 7-station lifecycle spine + a "law" section. The plan: 6 verbs + secondary Scan. **Ruling: the plan is right for this product's rollout wedge** (single-account, novice-first, P11), and Steadyhand — the persona closest to that wedge — lands nearest the plan. TradeDeck's density is a real need for the actual owner-operator, but it is better served by ⌘K, Fleet, and deep Results than by 10 rail items; Ledgerline's lifecycle spine is a beautiful *teaching* model that would tax everyday navigation — its lifecycle belongs *inside* the run/decision drill-in, not in the rail. The one structural point where all three out-vote the plan is the missing Runs/Activity forensic surface (§1.2.1) — that is a gap in the plan, not a reason to abandon six verbs. Resolve it as a first-class **Results → Activity/Runs sub-destination with a Run Inspector**, deep-linked from Dashboard's last-run line, rather than a seventh rail verb.

**D2 — Chat: tab or drawer?** Steadyhand makes Ask a top-level tab (the novice's escape hatch); TradeDeck and Ledgerline make it a context-aware drawer. The plan: persistent slide-over. **Ruling: drawer/slide-over wins (2/3 + plan)** — chat is a companion to surfaces, and a tab recreates the "two approval homes" bug. Steadyhand's underlying need (an ever-present "Ask about this" affordance that deep-links context) is already satisfied by spec/02's "why is this risky? → Assistant slide-over scoped to the card"; extend that affordance pattern to receipts/runs.

**D3 — Brain vs. fence.** Ledgerline independently reproduces the plan's exact split (Strategy Studio = offense; Risk & Policy = the cage) with the same reasoning. TradeDeck co-locates policy editing under Strategy but breaks out a read-only Risk cockpit. Steadyhand merges guardrails into one Strategy page for novices. **Ruling: the plan's Strategy/Guardrails split stands**, validated by Ledgerline's independent derivation; Steadyhand's novice concern is answered by the Guardrails 5-field Essentials layer, and TradeDeck's cockpit need is answered by the plan's "each Guardrails card doubles as live armed/tripped status" plus Dashboard gauges. Same ruling for the autonomy dial living in Guardrails (plan + Ledgerline's cage vs. Steadyhand's Strategy-page placement): arming is a containment decision.

**D4 — Scan prominence.** TradeDeck and Ledgerline give market/signals a top-level home; Steadyhand omits it almost entirely (novices meet evidence inside receipts). The plan: secondary read-only destination. **Ruling: the plan's middle position is correct** — it is exactly the average of the blind spread, and the palette covers the operator's one-keystroke need.

**D5 — Where does Flatten/Liquidate live?** Steadyhand puts Wind Down *inside* the emergency sheet as a typed third option; TradeDeck deliberately exiles LIQUIDATE to the bottom of the Risk page ("adjacency to panic buttons invites catastrophe"); the plan puts Flatten in Guardrails→Autonomy "and optionally a secondary button *inside* the STOP popover." **Ruling: TradeDeck is right; delete the plan's optional Flatten-in-STOP-popover.** The middle option a panicking user needs adjacent to STOP is **close-only** (all three designs offer it there), not liquidation. Steadyhand's counter-need (all stop verbs explained in one place) is satisfied by listing close-only inline and *linking* to Flatten with its consequences named.

**D6 — Confirm on halt?** All three blind designs use one confirm sheet (and use it as the education moment); the plan is more aggressive: zero-confirm one-click STOP ("friction on a panic button is a bug"). **Ruling: keep the plan's zero-confirm click — it is the better emergency mechanic — but this makes amendment A1 mandatory**, because the plan has deleted the only moment the blind designs used to teach "halting pauses synthetic stops." The education must move into the tooltip (corrected copy) and the immediate post-STOP persistent banner with a one-click "switch to close-only."

**D7 — Positions as a top-level destination.** TradeDeck and Ledgerline: yes; Steadyhand and the plan: on Home/Dashboard. **Ruling: plan wins at this product's scale** (a few names per account), provided working orders, stale-limit replace, protection status, and the reconciliation queue all render on Dashboard — the two operator designs' real content demands, not their nav placement.

**D8 — Fleet aggregation math.** TradeDeck: "real and simulated money never share an axis… the design never sums real and simulated money into one number." The plan's switcher shows "All accounts (Fleet) — aggregate net worth $312,540" summing all non-Test accounts (spec/01:168/182) — i.e., Live + Paper in one figure. **Ruling: TradeDeck is right and the plan should change.** The backend's own dual-bucket `FillSource` accounting takes a side here; the Fleet header should read "Live $X · Practice $Y."

## 3. NOVEL — concrete ideas the approved plan does not contain, worth adopting

Ranked by (convergence × leverage ÷ cost). Each names its source design(s).

1. **Run Inspector + Decision Receipt/Dossier** *(all three; TradeDeck §3.5, Ledgerline §3.3/3.4.1, Steadyhand §3.4/§4.6).* Per-run pipeline replay + chosen-and-skipped candidate table with skip reasons and since-decision returns + a permalinked layered per-decision artifact that notifications and chat deep-link into. Pure read-model over data already persisted; the highest-leverage unbuilt trust surface in the product.
2. **STOP-flow honesty kit** *(all three).* Corrected tooltip (drop "always safe" absolutism), post-STOP persistent banner naming what is now unguarded (synthetic stops paused; broker-held brackets still resting — per position), inline "switch to close-only," and "close-only is what circuit breakers choose" education.
3. **Confidence-calibration surfacing + evidence-gated Decide arming** *(all three surface it; Ledgerline §4.2 and Steadyhand §4.2 embed it in the arming ritual).* Add a Calibration scorecard to Results and render it (plus thesis scorecards and n-counts) inside the ARM DECIDE flow — "granting decide with n<20 closed trades is a design-failure signal" is a measurable product stance the plan can adopt wholesale.
4. **Chrome freshness/status strip** *(all three).* Data as-of + delayed-quotes disclosure + per-account next-run countdown; optionally TradeDeck's scheduler-heartbeat age as a liveness canary (amber >90s).
5. **One "Needs you" aggregation + a home for the learned-context queue** *(Steadyhand §1-2, TradeDeck §3.4, Ledgerline §3.2).* Dashboard block aggregating pending trade approvals, pending learned-context risk facts, tuning proposals, and reconciliation orphans; learned-context/tuning approvables join Approvals as a distinctly-shaped card class ("applies as advisory text only — never changes any number").
6. **Per-position protection column** *(all three).* `bracket @ broker` / `trailing 8% — synthetic, requires app up` / red `UNPROTECTED`, plus Ledgerline's coverage stat ("5/5 covered · 3 broker / 2 synthetic").
7. **Live gate pre-check on pending approval cards** *(TradeDeck §3.4, Ledgerline §3.4.1).* The card's checklist is a fresh server evaluation ("will pass / would block: daily cap after this order $792 of $500"), SSE/poll-refreshed, so a rejection is never discovered post-click.
8. **Thesis × regime track record line on the approval card** *(TradeDeck, Ledgerline).* One line from data the scorecards already compute; arguably the most decision-useful context an approver can get.
9. **Human-veto scorecard** *(Steadyhand §3.6, Ledgerline §3.4.2).* Aggregate "your rejections vs. your approvals" verdict atop Results→Counterfactuals — trust calibration for the human, both ways.
10. **Boot/auto-transition narration banners** *(all three).* "The system restarted at 06:12; autonomy dropped to Propose on all accounts (audited) [Review & re-arm]"; breaker-set close-only carries cause + timestamp on tap; hourly-cap demotion says "the AI hit your hourly limit and demoted itself to propose."
11. **Fire Drill + soft rehearsal gates** *(Steadyhand §3.1/§4.2; Ledgerline §4.2's "run it once in Paper first / arm anyway — type why").* Practice the STOP once in Test during onboarding; at ARM LIVE, interpose a soft check when the policy changeset has never run in Paper. Soft (skippable-with-reason), never hard — this is a self-hosted owner's tool, not a consumer app.
12. **Smaller adoptables:** object-naming typed phrases (`SELL LIVE POSITIONS — <alias>`); Ledgerline's batch-reject-never-batch-approve; exits pinned to the top of the approval queue with a shield tag (TradeDeck); Steadyhand's mobile "no swipe-to-approve" rule + honest command-lifecycle chips; per-field policy change history + required note on Live loosenings (Ledgerline's Policy Ledger — Results→History's before→after rows already cover ~80%; add the field-history glyph and the note).

Explicitly **not** recommended: TradeDeck's `[@lane] verb` palette grammar and Authority Ladder glyph (delightful, operator-only, high polish cost); Ledgerline's full commit-changeset model for all config edits (the plan's diff-and-confirm + impact preview covers the safety need at lower ceremony); Steadyhand's hard graduation gates with mandatory counts (patronizing for the actual user base — keep them soft); a top-level Runs rail item (fold into Results instead).

## 4. VALIDATION — the plan's four core bets against blind evidence

**Bet 1 — Six verb destinations: VALIDATED with one amendment.** All three blind designs organize primary nav by task, converge with the plan on Approvals/Home/Strategy(config)/Results(outcomes)/Settings(off-or-last), and 2/3 make chat a drawer. The count diverges by persona (7/10/7-stations vs. 6), which is exactly what the plan's novice-floor/power-ceiling principle predicts. The one place all three out-vote the plan is a prominent runs/activity forensic surface — adopt it inside Results rather than expanding the rail.

**Bet 2 — Account as primary object: STRONGLY VALIDATED.** TradeDeck's "scope before verb" Scope Bar that persists across destinations and colors the frame is the plan's switcher re-derived to the letter, including ALL-LANES ≈ Fleet and per-object danger styling in mixed lists. Ledgerline scopes the entire lifecycle spine to one account selected only in chrome; Steadyhand's Scope Pill rescopes the whole app with a live-account interstitial (≈ the plan's switch-into-Live acknowledgment). Nobody designed a "navigate to account" page. The plan's PR #7 gate (decouple view from execution before shipping the switcher) is also implicitly endorsed: all three assume switching is free, which today it is not — the plan is the only artifact that knows that, and its sequencing discipline is confirmed as necessary, not pedantic.

**Bet 3 — Scope-first settings: STRONGLY VALIDATED.** Three independent taxonomies drew the same line the plan prints on its divider, stamped blast radius on every surface, kept keys/channels/consent/presets-library user-global, kept all ~50 policy fields with the account, and 2/3 handled the `marketScan*` overlay exactly as the owner resolved Open Q1. Essentials-over-advanced also converges (Steadyhand's Guardrail Sentence + "50 dials under the hood"; Ledgerline's Simple mode as "a lens, never a separate store" — which precisely matches the plan's rule that Essentials binds to the same fields).

**Bet 4 — STOP/Flatten split: VALIDATED, with two convergent refinements.** All three separate halting from liquidation with the same rationale, want liquidation heavier and typed, and Steadyhand/Ledgerline independently derive the plan's asymmetric resume ("stopping is cheap; resuming is the ritual"). The refinements the plan should absorb: (1) the halt flow must disclose the synthetic-stop pause and offer close-only inline — unanimous, and the plan's current "Always safe" tooltip is the one piece of approved copy the blind evidence shows to be materially misleading; (2) Flatten should not sit inside the STOP popover (TradeDeck's adjacency argument; close-only takes that slot).

One further plan-internal bug the convergence exposes: the canonical doc's control-weaving paragraph reads "**Loosening** a limit is frictionless; raising a Live cap … triggers … confirm" — the first word must be "Tightening" (raising a cap *is* loosening). All three blind designs state the intended rule correctly ("the safe direction is always the cheap direction"); fix the sentence before it gets implemented literally.

## 5. AMENDMENTS — prioritized changes to the remaining delivery plan (PRs #9–#14)

**A1 · PR #9 (shell + STOP/Flatten) — STOP semantics honesty. [Highest priority; safety copy]**
Keep zero-confirm one-click STOP. Change: (a) tooltip/aria from "Always safe — never sells anything you hold" to "Halts everything in one click. Never sells. Pauses app-managed trailing stops; broker-held brackets keep protecting"; (b) on STOP, render a persistent post-halt banner naming what is now unguarded per position and offering one-click **Switch to close-only** and **Re-arm**; (c) add close-only as the STOP popover's second verb ("stop new buys, keep protective exits running — this is what circuit breakers choose"); (d) delete the "optional Flatten inside the STOP popover" clause — Flatten lives only in Guardrails→Autonomy. Update spec/01 §STOP, spec/09 §2.5/§6.4, and the shell tests (`shell-stop-never-sells` gains a "banner discloses synthetic-stop pause" assertion).

**A2 · PR #9 — chrome status strip.** Add to the shell: data as-of + delayed-quote disclosure, active account's next-run countdown ("market closed — next window Mon 9:30" when calendared), and a scheduler-heartbeat staleness indicator (amber >90s). All fields exist server-side.

**A3 · PR #10 (switcher) + PR #9 — narrated automatic transitions.** Boot-restart banner ("autonomy dropped to Propose on all accounts — [Review & re-arm]") rendered whenever PR #7's reset sweep fired since last session; tapping a `● close-only` / `‖ HALTED` suffix explains cause + timestamp (breaker, brake, human, boot); hourly-cap auto-demotion produces a placed notice. These are the UI half of machinery PR #7 already builds.

**A4 · PR #11 (Approvals) — four card upgrades.** (a) Specify the gate checklist on *pending* cards as a **live server re-evaluation** (SSE/poll-refreshed), showing "would block: <reason>" before the click; (b) add the thesis × regime track-record line (win rate, n) from the scorecard data; (c) pin Risk-Exit proposals above opening trades; (d) batch-reject allowed, batch-approve never. Also: extend the Approvals destination (or its spec) to host learned-context and tuning approvables as distinctly-shaped cards — the learned-context queue currently has no home anywhere in nav-v2.

**A5 · New PR (post-#11, before or with #12) — Run Inspector + decision permalinks.** Results → Activity/Runs sub-destination: run list → per-run drill-in (stage timeline, chosen-and-skipped table with skip reasons and since-decision returns, gate/breaker events verbatim, provenance chips) + a permalinked per-proposal detail page (the Receipt/Dossier) that notifications, chat answers, ledger rows, and blocked cards deep-link into. Read-only over persisted data; no schema change. This closes the largest 3/3 convergence gap.

**A6 · Results panel PR (whenever performance/tax panels move) — calibration + veto scorecard + bucket separation.** Add the confidence-calibration scorecard; add the human-veto summary atop Counterfactuals ("your rejections vs. your approvals"); require live vs. practice buckets never merge on one axis or one number. Then embed the calibration + thesis n-counts into spec/10 §3's ARM DECIDE ritual as the evidence panel.

**A7 · PR #12 (Fleet) — bucketed aggregates + machine-first rows.** Fleet header shows "Live $X · Practice $Y," never one summed net worth (amend spec/01:168/182). Fleet rows lead with state/authority/backlog/next-run and attach exceptional sub-rows (breaker tripped, interlock revert, `placing_failed`, stale limit) with inline actions — TradeDeck's fleet grammar, near-free once the data is plumbed.

**A8 · Dashboard spec (with #11 or #12) — protection column + reconciliation queue.** Positions gain the protection column (broker-held / synthetic-requires-app-up / red UNPROTECTED) and a wash-lock badge; a "Needs attention" region aggregates pending approvals, learned-context items, tuning proposals, and reconciliation orphans (`placing_failed`, `pending_reconciliation`) with Ledgerline's "No orphans — every order intent is accounted for" empty state.

**A9 · PR #14 (mobile) — approval-remote rules.** No swipe-to-approve ever (reject-swipe acceptable); approve always opens the full-screen sheet with the identical typed Live challenge, paste disabled; every command renders its queue lifecycle (`queued → running → succeeded/failed`) on the button itself — optimistic UI banned on the command path. Add to spec/11.

**A10 · spec/10 + copy deck — onboarding and phrase polish.** First run replays the live pipeline (reuse the Strategy Flow overlay in live mode) so the user's first minute is watching the stations light up; add a soft Fire-Drill step (press STOP once in Test) and a soft rehearsal interpose at ARM LIVE ("this policy has never run in Paper — run it once first / arm anyway, note why"). Typed phrases gain the object: `SELL LIVE POSITIONS — <alias>`, `ARM LIVE AUTONOMY — <alias>` (constants in spec/09 so client and server validator can't drift). Fix the "Loosening a limit is frictionless" sentence in the canonical doc (§Settings weaving paragraph) to "Tightening…".

Sequencing note: A1/A2 ride PR #9; A3 rides #9/#10; A4 rides #11; A7 rides #12; A9 rides #14; A5 and A6 are the only net-new work items, and both are read-models over already-persisted data — they slot cleanly after PR #11 without disturbing the #7 gate discipline, which this exercise leaves fully intact.
